Installation

How to install dependencies and structure your application with NNUI-KIT across Next.js, Vite, Astro, or plain HTML.

💡
Zero Framework Wrappers: NNUI-KIT runs directly on native Light-DOM Web Components. You write standard JSX / template tags without needing 5 separate adapter packages.
1

Create Project

Start by creating a new project with your framework of choice.

Terminal 
npx create-next-app@latest my-app --typescript --tailwind --eslint
2

Install NNUI-KIT

Add the core universal package to your project.

Terminal 
npm install nnui-kit
3

Configure Global Styles

Import the universal CSS and micro-enhancers in your app layout.

app/layout.tsx 
import 'nnui-kit/css';
import 'nnui-kit';
4

Configure Cascade Layers

Tailwind utilities override defaults cleanly without !important.

app/globals.css 
@import 'nnui-kit/css';

@tailwind base;
@tailwind components;
@tailwind utilities;
5

Add Your First Component

Render any component with native events and attributes.

app/page.tsx 
export default function Page() {
  return (
    
      

        
      

      
Welcome to NNUI-KIT

    
  );
}

Zero-Build CDN & Backend Quickstart

Pure Light-DOM web components engineered specifically for backend templates (HTMX, Django, Ruby on Rails, Laravel, and Alpine.js) with zero Node.js build step or hydration lag.

1. Universal CDN Quickstart

Paste these two lines into the <head> of any HTML document or server-side template to instantly unlock all 24 components:

HTML <head> CDN Links 
<!-- NNUI-KIT Universal Stylesheet (Cascade Layered + Shadcn Zinc Tokens) -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/nnui-kit/dist/index.css">

<!-- NNUI-KIT Light-DOM Runtime (< 4KB, Registers <ui-*> and <nnui-*> elements) -->
<script type="module" src="https://cdn.jsdelivr.net/npm/nnui-kit/dist/index.js"></script>

2. HTMX Hypermedia Integration

Because NNUI-KIT components operate entirely in the Light DOM and adhere to the strict "Mutate Attributes, Never Nodes" invariant, HTMX swaps (hx-swap="outerHTML" or innerHTML) work flawlessly without losing focus or breaking Shadow DOM hydration.

templates/users.html (HTMX) 
<!-- 1. Mount toaster once in base template -->
<ui-toaster position="bottom-right"></ui-toaster>

<!-- 2. Form submission with custom elements submitting natively -->
<form hx-post="/users/create" hx-target="#user-table" hx-swap="beforeend">
  <div data-ui="field">
    <label data-ui="label" for="role">User Role</label>
    <ui-select id="role" name="role" required>
      <button type="button" data-part="trigger">
        <span data-part="value">Select role...</span>
        <span>▾</span>
      </button>
      <ul data-part="listbox">
        <li data-part="option" data-value="admin">Administrator</li>
        <li data-part="option" data-value="editor">Editor</li>
      </ul>
    </ui-select>
  </div>

  <button type="submit" data-ui="button">Add User</button>
</form>

<!-- 3. Server response trigger for Toast notification -->
<!-- Server returns HTTP Header: HX-Trigger: {"showToast": "User added successfully"} -->
<script>
  document.body.addEventListener('showToast', (e) => {
    toast.success(e.detail.value || 'Operation completed');
  });
</script>

3. Python & Django Templates Integration

In Django, custom elements utilize standard ElementInternals form association. Inputs serialize directly into request.POST just like native <input> tags:

templates/profile.html (Django) 
{% extends "base.html" %}

{% block content %}
<form method="POST" action="{% url 'update_profile' %}">
  {% csrf_token %}
  
  <div data-ui="field">
    <label data-ui="label">Account Notification Volume</label>
    <ui-slider name="volume" value="75" min="0" max="100"></ui-slider>
  </div>

  <button type="submit" data-ui="button">Save Preferences</button>
</form>

{% if messages %}
<script type="module">
  import { toast } from 'https://cdn.jsdelivr.net/npm/nnui-kit/dist/index.js';
  {% for message in messages %}
    toast.{{ message.tags|default:"info" }}("{{ message|escapejs }}");
  {% endfor %}
</script>
{% endif %}
{% endblock %}

4. Ruby on Rails & Hotwire Turbo Integration

Rails Turbo Frames and Turbo Streams can dynamically stream server-rendered drawers, modals, and toasts:

app/views/orders/create.turbo_stream.erb (Rails) 
<!-- Append new order to list -->
<%= turbo_stream.prepend "orders_list", partial: "order", locals: { order: @order } %>

<!-- Trigger instant client-side toast -->
<script type="module">
  import { toast } from 'https://cdn.jsdelivr.net/npm/nnui-kit/dist/index.js';
  toast.success("Order #<%= @order.id %> placed successfully!");
</script>

Component Registry & CLI (npx nnui)

Just like shadcn/ui: install components directly into your own project source code. You own the code—zero black-box node_modules traps.

1. Explore Available Components

Terminal
npx nnui list

2. Initialize in Your Project

Creates your components/ui/ directory, base element utilities, and CSS tokens:

Terminal
npx nnui init

3. Add Specific Components

Download and configure components with automatic dependency resolution:

Terminal
# Install specific components
npx nnui add dropdown toast dialog tabs

# Or install the entire 24-component portfolio
npx nnui add --all
Docs / Getting Started / Architecture

Three-Tier Light-DOM Architecture

Why traditional component libraries hit an architectural dead end, and how NNUI-KIT inverts the stack into pure platform primitives.

Platform Tier Hierarchy 
+-------------------------------------------------------------------------+
| Tier 2: Micro-Enhancers (Light-DOM Custom Elements, < 4 KB JS)          |
| Focus management, APG roving tabindex, ElementInternals (Tabs, Combobox)|
+-------------------------------------------------------------------------+
| Tier 1: Platform Primitives (Native Browser Layout Engine)              |
| Popover API, <dialog>, CSS Anchor Positioning, Viewport Top-Layer       |
+-------------------------------------------------------------------------+
| Tier 0: Pure Semantic HTML + Tokenized Scoped CSS                       |
| Zero-JS first paint, 100% crawlable, @layer and @scope isolation       |
+-------------------------------------------------------------------------+

The 4 Core Engineering Invariants

1. Zero Shadow DOM

attachShadow() is strictly forbidden. All nodes reside in the document DOM. ID references (aria-labelledby, for, aria-controls) resolve natively across all screen readers (VoiceOver, NVDA, JAWS) with zero polyfills.

2. Mutate Attributes, Never Nodes

Custom elements track state exclusively by toggling attributes (data-state, aria-selected, tabindex). Enhancers never call appendChild() or remove nodes, preventing reconciliation crashes in React 19, Vue 3, and Svelte 5.

3. Defensive Cascade Layers (@layer)

All library CSS is declared in @layer ui.tokens, ui.reset, ui.base, ui.components, ui.overrides;. Consumer utility classes (Tailwind, UnoCSS) automatically win the cascade cleanly without ever needing !important.

4. Sub-4KB Core Runtime

By delegating overlays to the browser's top layer (popover, <dialog>) and positioning to CSS Anchor Positioning, main-thread JavaScript handles only state coordination and keyboard navigation.

Docs / Getting Started / Theming

Theming & Dark Mode

Built with an authentic high-contrast Zinc color scale, customized through CSS custom properties.

NNUI-KIT automatically respects system dark mode preferences via @media (prefers-color-scheme: dark). To force a theme programmatically, set the data-theme attribute on your root <html> element:

index.html 
<!-- Force Dark Theme -->
<html data-theme="dark">

<!-- Force Light Theme -->
<html data-theme="light">

Tailwind CSS Integration

Because NNUI-KIT is styled inside @layer ui.components, any Tailwind utility applied to component elements overrides library styles with zero specificity conflicts:

Example Component 
<!-- Tailwind classes (bg-zinc-800, text-emerald-400, rounded-2xl) win effortlessly -->
<button class="ui-button bg-zinc-800 text-emerald-400 rounded-2xl">
  Custom Styled Button
</button>

NNUI-KIT includes a standardized llms.txt file at the root of the project. AI coding assistants consume this plain-text manifest to understand exact tag names, required semantic child parts (data-part="input", data-part="listbox"), and event formats.
