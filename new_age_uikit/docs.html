Docs / Getting Started / Introduction

Introduction & Architecture

NNUI-KIT is a platform-native, three-tier Light-DOM universal UI system. It delivers accessible, composable components that work identically across React 19, Next.js 15, Vue 3, Svelte 5, Astro, HTMX, Django, Rails, and vanilla HTML without framework wrapper tax or Shadow DOM traps.

Tier 0 0 KB JS

Pure CSS Primitives

Button, Badge, Card, Avatar, Table, Input, Switch, Alert, Progress, Skeleton, and Separator. Instantly SSR-rendered with zero JavaScript hydration required.

Defensive Cascade: @layer ui.base
Tier 1 W3C DTCG

Design Tokens

Conforms to W3C Design Tokens Community Group standard. Synchronized between Figma Token Studio and CSS custom properties (--ui-*) with 6 themes.

File: tokens.json & Studio
Tier 2 Sub-4KB

Micro-Enhancers

Virtualized Data Grid (>15k rows), Date Range Picker, Combobox, Dialog, Popover, Tabs. Light-DOM custom elements with standard ARIA and native FormData.

Dual-Prefix: <ui-*> & <nnui-*>

Why Light-DOM? (Solving Shadow DOM Traps)

Traditional Web Component libraries lock their templates inside closed Shadow DOM trees. While encapsulation sounds good in theory, it introduces fatal problems in production enterprise applications. NNUI-KIT executes entirely in the document Light DOM:

Capability Shadow-DOM Components Framework Wrappers NNUI-KIT (Light-DOM)
HTML Form Submission Requires synthetic hidden inputs Requires synthetic hidden inputs ✓ Native ElementInternals & FormData
Global CSS Theming Broken; requires awkward ::part() Limited to proprietary config files ✓ 100% Cascade Layers & CSS Variables
Cross-Element ARIA aria-labelledby fails across roots Component-specific ID mangling ✓ W3C Standard Host Document ARIA
Framework Compatibility Requires custom React/Vue wrappers Locked to 1 framework (React or Vue) ✓ Works identically in all 7+ frameworks
Bundle Footprint 40 KB – 120 KB runtime 80 KB – 250 KB runtime ✓ Sub-4 KB core / 0 KB for Tier 0

Docs / Getting Started / SSR & Client Hydration

SSR & Client Hydration Safety

Node SSR Ready

How NNUI-KIT executes safely inside Node.js Server-Side Rendering (SSR), React Server Components (RSC), Next.js 15, Remix, and SvelteKit without ReferenceError: HTMLElement is not defined.

The Universal import 'nnui-kit/client' Entrypoint

Standard Web Components fail during server-side pre-rendering because Node.js lacks the browser's HTMLElement global. NNUI-KIT solves this at the base class layer with a 100% crash-free fallback (SafeBaseElement). When running on the server, all custom elements safely no-op; upon client hydration, they automatically register under both <ui-*> and <nnui-*> prefixes.

app/layout.tsx (Next.js App Router) 
// Import universal styles and the SSR-safe client entry
import 'nnui-kit/css';
import 'nnui-kit/client'; // Safe for Node SSR & Server Components!

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" data-theme="dark">
      <body>{children}</body>
    </html>
  );
}
⚡
Zero Package Size Overhead: Implementing the SSR safe entrypoint adds less than 30 bytes gzipped (0.015%) to the core library. Non-React projects (Vue, Svelte, HTMX) carry zero runtime overhead thanks to package subpath exports.

Official React 18 & 19 Wrapper

nnui-kit/react

Idiomatic React components with automatic ref forwarding, typed props, custom DOM event bridges, and automatic 'use client'; isolation.

Direct Ref Forwarding

Access native DOM APIs directly through standard React refs (e.g. gridRef.current.setColumns(), modalRef.current.showModal()). 

const gridRef = useRef(null);
// Calls native DataGrid method directly:
gridRef.current?.setRows(trades);

Custom DOM Event Bridging

Custom events (selection-change, sort, open) map automatically to standard camelCase React props (onSelectionChange, onSort). 

<DataGrid 
  onSelectionChange={(e) => setSelected(e.detail.selected)}
/>
app/dashboard/page.tsx 
'use client';

import { useRef, useState } from 'react';
import 'nnui-kit/client';
import { toast } from 'nnui-kit';
import { Tabs, DataGrid, Stepper, Dialog } from 'nnui-kit/react';

export default function DashboardPage() {
  const [tab, setTab] = useState('blotter');
  const gridRef = useRef(null);

  return (
    <div className="p-6 max-w-7xl mx-auto">
      <Tabs value={tab} onChange={(e) => setTab(e.detail.value)}>
        <div data-part="tablist">
          <button data-part="tab" data-value="blotter">Real-Time Blotter</button>
          <button data-part="tab" data-value="wizard">Order Slicer</button>
        </div>

        <div data-part="tabpanel" data-value="blotter">
          <DataGrid ref={gridRef} row-height="40" persist="url" sync="cross-tab">
            <div data-part="viewport" style={{ height: '400px', overflowY: 'auto' }}>
              <div data-part="runway">
                <table data-part="grid-table" className="ui-table">
                  <thead></thead>
                  <tbody data-part="virtual-tbody"></tbody>
                </table>
              </div>
            </div>
          </DataGrid>
        </div>
      </Tabs>
    </div>
  );
}

Docs / Getting Started / Architecture

Three-Tier Light-DOM Architecture

Why traditional component libraries hit an architectural dead end, and how NNUI-KIT inverts the stack into pure platform primitives.

Platform Tier Hierarchy 
+-------------------------------------------------------------------------+
| Tier 2: Micro-Enhancers (Light-DOM Custom Elements, < 4 KB JS)          |
| Focus management, APG roving tabindex, ElementInternals (Tabs, Combobox)|
+-------------------------------------------------------------------------+
| Tier 1: Platform Primitives (Native Browser Layout Engine)              |
| Popover API, <dialog>, CSS Anchor Positioning, Viewport Top-Layer       |
+-------------------------------------------------------------------------+
| Tier 0: Pure Semantic HTML + Tokenized Scoped CSS                       |
| Zero-JS first paint, 100% crawlable, @layer and @scope isolation       |
+-------------------------------------------------------------------------+

The 4 Core Engineering Invariants

1. Zero Shadow DOM

attachShadow() is strictly forbidden. All nodes reside in the document DOM. ID references (aria-labelledby, for, aria-controls) resolve natively across all screen readers (VoiceOver, NVDA, JAWS) with zero polyfills.

2. Mutate Attributes, Never Nodes

Custom elements track state exclusively by toggling attributes (data-state, aria-selected, tabindex). Enhancers never call appendChild() or remove nodes, preventing reconciliation crashes in React 19, Vue 3, and Svelte 5.

3. Defensive Cascade Layers (@layer)

All library CSS is declared in @layer ui.tokens, ui.reset, ui.base, ui.components, ui.overrides;. Consumer utility classes (Tailwind, UnoCSS) automatically win the cascade cleanly without ever needing !important.

4. Sub-4KB Core Runtime

By delegating overlays to the browser's top layer (popover, <dialog>) and positioning to CSS Anchor Positioning, main-thread JavaScript handles only state coordination and keyboard navigation.

Docs / Getting Started / Form Validation

Form Validation (React Hook Form & Zod)

First-class integration with schema validation libraries. Light-DOM inputs and custom elements wire into form state using native attributes.

Default State
We will never share your personal email.
Error State (aria-invalid="true")
Please enter a valid business email address.

React 19 + React Hook Form + Zod Implementation

Use React Hook Form's register() for native inputs or Controller for composite custom elements (like <ui-tags-input> or <ui-date-range-picker>):

app/components/RegistrationForm.tsx 
import { useForm, Controller } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import * as z from 'zod';
import 'nnui-kit';

const formSchema = z.object({
  email: z.string().email('Please enter a valid email address'),
  skills: z.array(z.string()).min(1, 'Please add at least one skill tag'),
});

type FormData = z.infer<typeof formSchema>;

export function RegistrationForm() {
  const { register, control, handleSubmit, formState: { errors } } = useForm<FormData>({
    resolver: zodResolver(formSchema),
  });

  const onSubmit = (data: FormData) => {
    console.log('Valid Form Submission:', data);
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)} className="space-y-6 max-w-md">
      
      {/* 1. Native Input with Zod Validation */}
      <div data-ui="stack" data-direction="col" data-gap="1">
        <label data-ui="label" htmlFor="email-input">Work Email</label>
        <input
          data-ui="input"
          id="email-input"
          {...register('email')}
          aria-invalid={Boolean(errors.email)}
          aria-describedby={errors.email ? 'email-error' : 'email-hint'}
        />
        {errors.email ? (
          <span data-ui="field-error" id="email-error">{errors.email.message}</span>
        ) : (
          <span data-ui="field-hint" id="email-hint">We will send your verification link here.</span>
        )}
      </div>

      {/* 2. Custom Element Tags Input via Controller */}
      <div data-ui="stack" data-direction="col" data-gap="1">
        <label data-ui="label">Technical Skills</label>
        <Controller
          name="skills"
          control={control}
          render={({ field }) => (
            <ui-tags-input
              placeholder="Add skill (e.g. React)..."
              onChange={(e) => field.onChange(e.detail.tags)}
            />
          )}
        />
        {errors.skills && (
          <span data-ui="field-error">{errors.skills.message}</span>
        )}
      </div>

      <button type="submit" className="ui-button">Submit Application</button>
    </form>
  );
}

Docs / Platform Innovations / Triple-Sync & AI Protocol

Triple-Synchronized UI & AI Protocol

Platform Innovation

Declarative state persistence, zero-latency multi-tab sync, CSS container query polymorphic morphing, and autonomous AI introspection (element.inspectAI()).

🔗

Declarative State Persistence

No router code or Redux boilerplate. Simply add persist="url" to sync search, sort, and pagination state directly into URL query parameters (e.g. ?page=2&search=btc), or persist="local" to autosave drafts and wizard progress across page refreshes. 

<!-- Automatically syncs search & filters to URL -->
<ui-data-grid persist="url" sync="cross-tab"></ui-data-grid>

<!-- Autosaves step progress across browser reloads -->
<ui-stepper persist="local" sync="cross-tab"></ui-stepper>
⚡

Real-Time Multi-Tab Synchronization

Add sync="cross-tab" to any interactive component. It utilizes zero-overhead Web BroadcastChannel primitives to immediately reflect user actions across all open browser windows and tabs without needing a WebSocket server or polling. 

// Zero backend required. When user changes step in Tab 1,
// Tab 2 updates instantly in sub-millisecond real time:
<ui-stepper sync="cross-tab">...</ui-stepper>
🤖

Machine-Readable AI Protocol

Every NNUI-KIT element implements element.inspectAI() conforming to protocol nnui.ai.v1. Autonomous coding agents (Cursor, Claude, Antigravity) can query elements directly to discover valid attributes, live state, and generate 100% accurate framework code. 

const schema = await element.inspectAI();
console.log(schema.protocol); // 'nnui.ai.v1'
console.log(schema.state);    // Live runtime snapshot
console.log(schema.snippets); // React 19, Vue 3, Svelte 5

Design Tokens & DTCG Standard

Token taxonomy conforming to the W3C Design Tokens Community Group (DTCG) specification for unified cross-tooling synchronization with Figma and code.

NNUI-KIT organizes tokens across a 3-tier architecture: Reference Tokens (raw scale values), System/Semantic Tokens (role-based variables like --ui-bg-surface or --ui-text-primary), and Component Tokens.

🎨 Color Scales

50 to 950 stepped lightness shades, with dark-mode inverted semantic roles.

⚡ Motion Curves

Cubic-bezier spring physics (--ui-ease-spring, --ui-ease-bounce).

📐 Unified Elevation

Strict Z-index scales (--ui-z-dropdown 1000 through --ui-z-tooltip 1500).

W3C DTCG Token Export (`tokens.json`)

NNUI-KIT includes a first-class tokens.json conforming to the W3C Design Tokens Community Group specification. Import it directly into Figma Token Studio or Style Dictionary:

tokens.json (W3C DTCG Format) 
{
  "$schema": "https://design-tokens.github.io/community-group/format/",
  "color": {
    "brand": {
      "600": { "$type": "color", "$value": "#6366f1", "$description": "Primary accent violet" }
    }
  },
  "elevation": {
    "z-dropdown": { "$type": "number", "$value": 1000 },
    "z-modal": { "$type": "number", "$value": 1300 },
    "z-toast": { "$type": "number", "$value": 1400 }
  }
}

Docs / Design System / Accessibility

Accessibility & Motion Standards

Built-in guardrails for WCAG 2.1 AA compliance: reduced-motion safety, Windows High Contrast Mode, and screen reader announcements.

🏃 Vestibular Motion Safety (`prefers-reduced-motion`)

When users configure system-level reduced motion preferences, NNUI-KIT automatically reduces animation durations to 0.001ms and disables transform translations, satisfying WCAG 2.1 Criterion 2.3.3.

👁️ High Contrast Mode (`forced-colors`)

Components adapt to Windows High Contrast Mode by mapping outlines to system colors (CanvasText, Highlight, ButtonFace), preserving visual boundaries even when background images and box shadows are stripped.

🔊 Screen-Reader Only Utility (`.ui-sr-only`)

Hide visual content while keeping it fully announced by VoiceOver, NVDA, and JAWS using class="ui-sr-only" or data-ui="sr-only".
